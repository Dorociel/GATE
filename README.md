# GATE Verilog 계층도 생성기

버전 0.1.0 · 초기 시제품(사용자 직접 확인 미완료) · Windows 데스크톱 프로그램(Electron)

## 소개와 제작 목적

Verilog 코드를 붙여넣으면, 프로그램이 모듈 정의와 모듈 안의 인스턴스를 직접 찾아 **모듈 계층도**를 만들어 줍니다. 칩·MCU처럼 모듈이 많은 RTL 코드에서 "어떤 모듈이 어떤 하위 모듈을 몇 번, 어떤 이름으로 인스턴스화하는지"를 한눈에 보려는 목적입니다.

- 사용자가 부모·자식 관계나 JSON을 직접 쓰지 않습니다. Verilog 코드만 입력합니다.
- 서버·로그인·AI API를 사용하지 않으며 코드를 외부로 보내지 않습니다(프로그램에 네트워크 기능 없음).
- **간이 텍스트 분석**입니다. 모든 Verilog 문법을 지원하지 않습니다(아래 "지원 범위와 제한사항").

## 분석 목록과 여러 파일 통합 설계

왼쪽 위 `분석 목록`에서 분석 항목을 여러 개 만들고 전환합니다. 항목마다 소스·결과·선택·상세·신호 연결 상태가 따로이며 서로 섞이지 않습니다.

- `+ 새 분석` → **단일 소스**: `파일 불러오기`(.v/.sv 하나) 또는 `직접 입력(붙여넣기)`
- `+ 새 분석` → **통합 설계**: 이름을 정한 뒤 `파일 불러오기`(여러 개 선택) 또는 `소스 직접 작성`(파일명+코드 입력, 앱 안에서만 생성). 같은 버튼 두 개는 선택된 통합 설계 항목 바로 아래에 항상 보이며, 항목을 우클릭해도 같은 메뉴가 열리고, 탐색기에서 .v/.sv 파일(여러 개 가능)을 설계 항목 위로 끌어 놓아도 추가됩니다. 여러 소스를 한 설계로 묶어 파일 사이의 모듈 인스턴스 연결을 이어서 분석하며, 줄 번호는 항상 **그 파일 기준**입니다.
- 통합 설계의 파일을 누르면 **소스 표시만** 바뀝니다(분석 범위는 설계 전체 그대로). 파일별 체크박스로 `분석 포함`을 끌 수 있고, `×`는 **목록에서만** 제거합니다. 원본 파일은 읽기만 하며 수정·삭제하지 않습니다. 입력창에서 고친 내용은 프로그램 안의 사본에만 반영됩니다.
- 같은 이름의 파일을 추가하면 알리고 `이번 추가 건너뛰기` / `별도 소스로 추가`(예: `cpu (2).v`, 원래 파일명·모듈명은 그대로)를 고르게 합니다. 경로를 알 수 없어 "같은 파일"이라고 확정하지 않습니다.
- 서로 다른 파일(또는 한 파일 안)에서 **같은 모듈명이 둘 이상 정의되면 충돌**로 표시하고 어느 쪽을 쓸지 정하지 않습니다. 충돌 모듈에 도달하는 최상위는 계층도를 만들지 않으며, 해당 파일을 `분석 포함` 해제하거나 제거해 해결합니다. 선택한 최상위에서 인스턴스화되지 않는 모듈은 `인식 결과`에 따로 나열하고 임의로 연결하지 않습니다.
- 모듈 상세에는 정의 파일·파일 기준 줄 번호·사용 위치(인스턴스 선언 파일·줄)·원본 소스가, 신호 연결 탭에는 대상 모듈의 정의 파일이 표시됩니다. `Markdown 복사`에도 정의 파일명이 들어갑니다.
- 화면에 표시되는 안내: 분석 목록은 저장되지 않고 앱 종료 시 사라짐 / `.sv`를 고를 수 있다고 SystemVerilog를 지원하는 것은 아님 / `` `include``는 처리하지 않고 대상 파일을 자동으로 찾지 않음 / 파일 읽기 실패 / 파일 크기 한도(2MB 초과는 불러오지 않음, 분석 한도 약 30만 자) / UTF-8로 읽음(깨진 글자가 있으면 파일별 안내).
- 선택할 수 있는 확장자는 `.v`, `.sv`뿐입니다(`.vh` 불가). 폴더 통째 불러오기·분석 목록 저장/복원은 지원하지 않습니다(후속 계획).

## 주요 기능 (현재 구현)

- Verilog 코드 입력, `코드 분석`
- 인식한 모듈·인스턴스 목록 확인 (`인식 결과` 탭): 모듈별 섹션과 표(인스턴스명, 모듈명, 정의 여부, 포트 연결 형식, 줄 번호). 긴 식별자는 줄바꿈으로 전체를 볼 수 있음
- `Markdown 복사`: 인식 결과를 Markdown 텍스트로 클립보드에 복사(`인식 결과` 탭)
- 오류와 지원하지 않는 문법 안내(경고 상자: 제목에 `경고`를 표시해 색상에만 의존하지 않음)
- 상단 요약: 계층도 탭은 `최상위 모듈 · 계층도 블록 수 · 깊이`, 인식 결과 탭은 `모듈 정의 수 · 인스턴스 선언 수 · 확인 필요 건수`를 표시. 세 숫자는 서로 다른 값임 — 모듈 정의 수는 입력 코드의 `module` 개수, 인스턴스 선언 수는 입력 코드 전체의 인스턴스 선언문 개수, 계층도 블록 수는 선택한 최상위부터 펼친 블록 수(같은 모듈도 인스턴스마다 1개)
- 헤더의 `지원 문법 안내` 버튼: 지원 범위와 제한사항을 대화상자로 표시(`닫기` 버튼·Esc·바깥 클릭으로 닫힘)
- 최상위 모듈 선택(어디서도 인스턴스화되지 않은 모듈은 `최상위 후보` 표시)
- 계층도 생성: 상위 모듈은 왼쪽, 하위 모듈은 오른쪽, 같은 깊이는 같은 열. 블록에 모듈명과 인스턴스명 표시
- 같은 모듈을 여러 번 쓰면 인스턴스마다 별도 블록
- 정의가 없는 모듈은 `정의 미제공`, 재귀 인스턴스화는 `재귀`로 표시하고 펼치지 않음
- 큰 계층도는 스크롤로 확인
- 블록을 한 번 누르면 선택(강조)만, **두 번 누르거나 Tab으로 이동해 Enter**를 누르면 오른쪽에 `모듈 상세` 패널이 열림: 모듈명, 인스턴스명, 최상위부터의 전체 인스턴스 경로, 모듈 정의 시작 줄, 직접 하위 인스턴스, 해당 모듈의 원본 소스 코드. 정의가 없으면 `정의 미제공`, 하위가 없으면 `하위 모듈 없음`
- 상세 패널의 `이 모듈 중심으로 계층 보기`(그 블록 아래만 다시 그림, `전체 계층으로`로 복귀), `이 모듈의 신호 연결 보기`, `닫기`
- `신호 연결` 탭(카드형 목록): 대상 모듈의 경계 포트와 **직접 하위 인스턴스** 포트 중 단일 신호명으로 연결된 항목을 신호별로 묶어 표시. 연결 그래프(선)는 그리지 않음

화살표는 **인스턴스화 관계**(상위가 하위를 인스턴스화함)만 뜻합니다. 데이터 흐름이나 신호 연결이 아닙니다.

### 신호 연결 탭의 규칙과 제한 (화면에도 표시됨)
- 대상: 선택한 모듈의 경계 포트 ↔ 직접 하위 인스턴스 포트. 하위 모듈 내부를 따라가는 추적은 하지 않습니다.
- 방향: 인스턴스 포트의 `input`은 신호를 받음(수신), `output`은 신호를 구동. 선택 모듈 자신의 경계 포트는 반대로 봅니다(`input` = 안쪽 신호를 구동, `output` = 받음). `inout`, 정의 없는 모듈·포트는 연결 사실만 남기고 방향 없음(구동·수신 판정에서 제외).
- 비트 선택, 연산식·연결 연산, 상수, 빈 연결, 위치 기반, `.*` 연결은 분석에서 제외하고 `분석 제외 연결`에 사유와 함께 표시합니다.
- 구동 포트가 없으면 `알려진 구동 포트 없음`(assign/always 등은 분석하지 않으므로 구동원이 없다는 뜻이 아님)으로만 표시합니다.
- 폭을 계산할 수 없으면 `폭 미확인`. 인스턴스 배열은 폭을 판단하지 않습니다.
- 신호 연결의 대상은 계층도의 최상위 선택과 별개입니다(상세 패널에서 열어도 최상위 선택은 바뀌지 않음). 코드를 다시 분석하거나 수정하면 선택·상세·부분 계층 상태가 초기화됩니다.

## 설치 및 실행 방법 (Windows)

필요한 것: **Node.js**(LTS 권장, 개발 PC에서는 v24.22.1 확인) 와 인터넷 연결(Electron 내려받기, 첫 실행 시 100MB 이상). 의존성은 `electron` 하나입니다(`package.json`, 개발 의존성).

> **중요: 로컬 드라이브(C: 등)에서 실행하세요.** 네트워크 공유 드라이브에서는 Electron 45가 시작 직후 종료되는 것이 확인되었습니다. 소스를 네트워크 드라이브에 두었다면 로컬 폴더로 복사해서 실행합니다.

PowerShell 예시 (`C:\work\gate-verilog-hierarchy`는 예시 경로):

```powershell
robocopy <원본 폴더> C:\work\gate-verilog-hierarchy /E /XD node_modules
cd C:\work\gate-verilog-hierarchy
npm.cmd ci --include=dev
npm.cmd start
```

- `npm` 대신 `npm.cmd`: PowerShell 실행 정책이 `npm.ps1`을 막는 PC가 있습니다(개발 PC에서 확인). 명령 프롬프트(cmd)에서는 `npm`도 됩니다.
- `--include=dev`: 환경변수 `NODE_ENV=production`이 설정된 PC에서는 개발 의존성(electron)이 설치되지 않기 때문입니다(개발 PC에서 확인). 해당 설정이 없으면 생략해도 됩니다.
- `npm ci`는 `package-lock.json`(electron 45.5.0)에 맞춰 설치합니다.
- 설치 후 첫 `npm.cmd start`에서 Electron 실행 파일을 내려받으므로 처음에는 시간이 걸립니다.
- 별도 창이 열리면 Claude나 브라우저를 닫아도 계속 쓸 수 있습니다. 창을 닫으면 종료됩니다.
- `.exe` 파일은 아직 만들지 않았습니다(아래 "향후 개선사항").

로직만 검사하려면(화면 없음, 어느 드라이브에서나 가능): `node test\check.js`

## 사용 순서

1. 왼쪽 `Verilog 소스` 입력창에 코드를 붙여넣습니다(처음에는 예제가 들어 있습니다).
2. `코드 분석`을 누릅니다. `인식 결과` 탭에서 모듈·인스턴스 목록과 경고를 코드와 대조해 확인합니다.
3. `최상위 모듈` 선택 상자에서 기준 모듈을 고릅니다(분석 전에는 비활성).
4. `계층도 생성`을 누르면 `계층도` 탭에 선택한 모듈 아래의 계층이 표시됩니다(분석 전에는 비활성).
5. 코드를 수정하면 다시 `코드 분석`을 눌러야 합니다.
6. 지원하는 문법이 궁금하면 오른쪽 위 `지원 문법 안내`를 누릅니다.
7. 계층도에서 블록을 두 번 누르면(또는 포커스 후 Enter) 모듈 상세가 열립니다. 상세 패널의 버튼으로 부분 계층 보기·신호 연결 보기를 쓸 수 있습니다. `counter_system` 예제는 `examples/counter_system.v`에 있습니다(상수·비트 선택 연결이 일부러 들어 있어 제외 표시를 확인할 수 있음).

## 예제와 예상 계층도

`examples/basic_top_child.v` (입력창 기본 예제와 같음): `top`이 `child`를 두 번 인스턴스화하고, `child`가 `leaf`를 하나 인스턴스화합니다. 요약:

```verilog
module top (input clk, input rst_n, output [7:0] out_a, output [7:0] out_b);
  child u_child_0 (.clk(clk), .rst_n(rst_n), .dout(out_a));
  child #(.WIDTH(8)) u_child_1 (.clk(clk), .rst_n(rst_n), .dout(out_b));
endmodule
module child (input clk, input rst_n, output reg [7:0] dout);
  leaf u_leaf (.clk(clk));
  ...
endmodule
module leaf (input clk);
endmodule
```

최상위를 `top`으로 선택했을 때 예상 결과(`블록 5개 · 깊이 3단계`):

```
top (최상위)
├─ u_child_0 : child
│    └─ u_leaf : leaf
└─ u_child_1 : child
     └─ u_leaf : leaf
```

화면에서는 `top` 블록이 왼쪽, `child` 블록 2개가 가운데 열, `leaf` 블록 2개가 오른쪽 열에 놓이며 직각 화살표로 이어집니다. 주석 처리된 `// child u_old (...)`는 무시됩니다.

## 지원 범위 및 알려진 제한사항

지원:
- `module ~ endmodule` 정의, 여러 모듈을 한 번에 붙여넣기
- `모듈명 [#(...)] 인스턴스명 (.포트(신호), ...);` 형식(이름 기반 포트 연결), 선언문당 인스턴스 1개
- `//`, `/* */` 주석 무시

지원하지 않음(해당 구문이 있으면 화면에 경고하지만 완전히 분석한 것처럼 처리하지 않습니다):
- `generate`/`genvar` 안의 인스턴스, 매크로·`` `ifdef``·`` `include`` 등 컴파일러 지시어
- SystemVerilog 문법(`logic`, `interface`, `package` 등)
- 위치 기반 포트 연결, `.*`, 인스턴스 배열, 쉼표로 이어진 다중 인스턴스 — 인스턴스 관계만 인식하고 경고
- 게이트 프리미티브(`and`, `or` 등)는 모듈로 취급하지 않음
- 버스 프로토콜 해석, 주소 맵, 파라미터 값 계산, 하위 계층을 관통하는 신호 추적, 신호 연결 그래프(선) 그리기 (신호 연결 탭은 위 규칙의 단순 카드 목록만 제공)
- 입력 코드에 정의가 없는 모듈은 `정의 미제공`으로 표시하며 내부를 펼치지 않음
- 계층 블록이 1500개를 넘으면 일부를 생략하고 안내
- "인스턴스처럼 보이지만 인식하지 못했습니다" 경고는 패턴 검사라 오탐이 있을 수 있고, 일부 구문은 경고 없이 놓칠 수 있습니다. `인식 결과`를 항상 코드와 대조하세요.
- 긴 이름은 블록 안에서 `…`로 줄여 표시됩니다(마우스를 올리면 전체 이름).

## 현재 구현 기능과 향후 개선사항

현재 구현(코드 작성 완료): 위 "주요 기능" 전체.

실행 확인 상태: Node 로직 검사(86개: 기존 29 + 신호 연결·상세용 21 + 여러 파일 통합 로직 31 + Markdown·범위·제외 5)와, 개발 PC(Windows)의 로컬 드라이브 복사본에서 디버깅 포트(CDP)와 스크린샷으로 자동 확인한 화면 흐름: 창 실행·분석·계층도·탭 전환·지원 문법 대화상자·Markdown 복사·오류 표시·대형 입력 스크롤, 그리고 분석 목록(`+ 새 분석` 메뉴, 통합 설계 생성, 실제 `input[type=file]` 경로로 파일 추가, 같은 이름 선택 창, 모듈명 충돌 차단과 해결, 분석 제외, 파일 전환, 항목 간 상태 분리, 제거 확인, 확장자·크기·읽기 실패·UTF-8·.sv·include 안내, 파일별 상세·신호 연결). 사람이 마우스·키보드로 직접 조작하는 확인(모듈 상세·신호 연결·분석 목록 포함), 실제 파일 선택 대화상자 조작, 화면 배율(DPI) 변경, 실제 RTL 코드는 아직 확인하지 않았습니다.

화면 디자인: 밝은 테마(연회색 배경, 흰색 패널, 남색 글자, 파란 주요 버튼). 외부 웹폰트·아이콘을 쓰지 않으며 코드와 식별자에만 고정폭 글꼴(Consolas 계열)을 사용합니다.

## 신호 연결 그래프 · 연결 방향 애니메이션 · VCD 재생 · 테스트벤치 분석

‘신호 연결’ 탭의 [카드]/[그래프] 전환과 ‘테스트벤치’ 탭에서 쓰는 기능입니다. 모두 소스를 **읽어서** 보여 주는 것이며 시뮬레이터가 아닙니다.

| 기능 | 지원하는 범위 | 지원하지 않거나 제한되는 것 |
|---|---|---|
| 신호 연결 그래프 | 선택한 모듈의 경계 포트, 직접 하위 인스턴스, 단일 신호명 연결을 선으로 표시. 신호·포트를 누르면 같은 신호 강조. 다중 구동·정의 미제공·방향 미확정 경고 유지 | 분석하지 못한 연결(식·연결 연산·배열 등)은 ‘제외’ 항목으로 표시만 하며 선을 긋지 않음. 계층을 관통하는 신호 추적 없음. 계층도의 포함 관계 선은 신호선이 아님 |
| 연결 방향 애니메이션 | 확정된 구동 포트 → 신호 → 수신 포트 방향에만 점 이동. 재생/일시정지·속도 | inout·방향 미확정은 점선(방향 없음). 점의 속도·순서는 회로 지연이 아님. 실제 시뮬레이션이 아님 |
| VCD 재생 | 기존 VCD 파일 불러오기, 시점 이동(슬라이더·처음·이전/다음 값 변경), 재생/일시정지·속도, 그래프에 현재 값 표시, 변한 신호 강조, 0/1·X/Z·벡터 구분, 시간 단위·현재 시각, 기준 경로 선택(DUT가 테스트벤치 아래일 때), 연결하지 못한 신호 목록 | 시뮬레이터를 실행하지 않음. 이름이 맞지 않는 신호는 임의로 연결하지 않음. 파일 크기·변경 수 상한(8MB·100만 건) 초과분은 잘라내고 경고 |
| 테스트벤치 분석 | 파일 역할(설계/테스트벤치) 지정, 테스트벤치·DUT 후보, DUT 상세 보기 이동, 클록·리셋·입력 자극·대기 조건·출력 비교·종료/실패 조건 표시(근거 코드·파일·줄 번호, ‘코드 확인’/‘추정’ 구분), initial/always 블록별 분리 표시 | task/function, fork/join, case, generate, force/release, $random, 파일 입출력은 ‘분석 미지원·추가 확인 필요’. 코드를 실행하지 않으므로 통과·실패를 판정하지 않음. 블록 간 실행 순서·경쟁 판단 없음. 시각은 같은 initial 안에서 #지연만 거친 경우만 계산 |

## 계층도 탐색·포트 표시 (제자리 펼치기/접기)
- 블록 더블클릭, 오른쪽 위 ▸/▾ 버튼, Enter/→/← 키로 해당 인스턴스의 바로 아래 하위만 제자리에서 펼치거나 접습니다. 부모·형제는 그대로 남고, 펼침 상태는 인스턴스 전체 경로 단위로 따로 기억합니다(같은 모듈의 다른 인스턴스는 서로 영향 없음).
- 정의 없는 모듈·재귀·말단은 펼침 표시가 없습니다. "모두 펼치기/모두 접기" 버튼, 처음 표시는 최상위의 바로 아래까지입니다.
- 상세 정보는 블록 왼쪽 위 ⓘ 버튼(또는 i 키)으로 엽니다. 상세 패널을 열고 닫아도 펼침 범위는 바뀌지 않으며, "이 모듈 중심으로 보기"는 따로 누를 때만 부분 계층으로 바꿉니다. 패널 폭은 분리선(끌기/←→ 키/더블클릭 초기화)으로 조절합니다.
- 블록 안: 입력 포트는 왼쪽, 출력·inout은 오른쪽, 포트명+비트폭과 상위에서 연결된 신호를 구분해 표시합니다. 방향·폭을 알 수 없으면 "미확인"으로 두고 추정하지 않습니다. 포트가 많으면 일부만 보이고 "전체 포트 보기"(또는 p 키)로 모두 표시합니다. 긴 이름은 말줄임 + 마우스 올리면 전체 이름이 보입니다.
- 지원 범위 밖(미구현): 회로도 변환(Yosys 등), RTL/게이트 기호, 레지스터 비트 칸, 게이트 수준 VCD 값 표시. 현재 환경에 yosys/netlistsvg/iverilog/verilator는 설치돼 있지 않습니다.
- 테스트: npm test (check, check_sim, check_tb, check_tree, check_ports). 화면 확인은 자동(CDP, 합성 이벤트)이며 사용자 직접 확인은 별도입니다.
